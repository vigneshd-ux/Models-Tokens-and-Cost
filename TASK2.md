## Hand verification

- Arithmetic was recalculated in order above; with the stated cent-rounding convention the total is **$79.14**. Changing whether tax applies to shipping or whether discount rounding is done per item would change the result, so the prompt makes those assumptions explicit.
- Logic: choose an element that is both a wug and a nim (guaranteed by “some wugs are nims”). Every wug is a plim, and no plim is a zor; therefore that element is a nim that is not a zor. The answer is **yes**.

## Five safeguards for a business application

1. **Ground factual answers:** retrieve from approved, current sources; require citations or source IDs and abstain when supporting evidence is missing.
2. **Validate outputs:** enforce JSON schemas, enumerated labels, length bounds, and deterministic checks for amounts, dates, IDs, and calculations.
3. **Limit actions and defend trust boundaries:** treat user documents as data, isolate instructions from retrieved text, use least-privilege tools, and require confirmation for consequential actions.
4. **Escalate by risk:** route sensitive, financial, security, ambiguous, or low-confidence cases to a trained person; make the handoff path visible.
5. **Monitor and reevaluate:** log model/version, prompt, sources, latency, cost, and outcome with privacy controls; review sampled failures and rerun a representative evaluation set after changes.

## Interpretation

The examples show that fluent output can be wrong: the unguarded invented-paper answer sounds specific but has no evidence. Adding an uncertainty instruction improved this one response, but a single pair does not prove the prompt prevents hallucinations generally. The same caution applies to context retrieval and reasoning: correct answers on constructed examples do not guarantee production reliability. Keep human review and deterministic validation around high-impact decisions.
